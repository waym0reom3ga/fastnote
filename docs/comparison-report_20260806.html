HISTORIC ARTIFACT — RETAINED AS EVIDENCE, NOT AS RESULTS

Superseded 2026-08-07. Every figure below is invalid. This report was generated from a test suite that did not test the applications. The "35/35 passed" results were produced by tests that exercise only the model, renderer and exporter libraries — the layers that were already correct. No test in the suite ever constructed a GUI widget or simulated a user action.

The UI-layer tests (24–28) were tautological. Representative example: ASSERT(app->editor_text != NULL) where editor_text is a fixed-size array inside a calloc'd struct — an assertion that cannot fail at runtime.

Verified at time of supersession: 0 of 11 ports could open an arbitrary file (no file-open dialog existed anywhere in the repository); only 2 of 11 wrote an export file to disk; 3 ports produced no runnable binary at all; and the 4 Python "ports" were a single headless library cloned four times with no GUI toolkit imported and no entry point.

Key Findings

Fastest: C. All 3 C editions (Nuklear, GTK4, RayGUI) run in ~0.08-0.09s. Compiled ahead-of-time, minimal runtime overhead.

Rust is 10-30x slower than C on test startup. Rust/GTK4 at 0.28s, Rust/egui at 0.56s, Rust/Slint at 0.97s. This is dominated by test harness startup (cargo test), not the actual test execution (0.01s reported by cargo).

Go split is real. Go/Gio (1.87s) vs Go/Fyne (4.97s). Fyne's headless UI test driver adds overhead from screenshot capture and widget tree rendering. Gio tests are pure unit tests.

Python editions are identical. All 4 Python editions (GTK4, PyQt6, PySide6, DearPyGui) run at 3.01-3.08s. The bottleneck is Python interpreter + pytest startup, not the GUI framework. The model/renderer/exporter layers are literally the same files.

Smallest binary: Rust/GTK4 at 666KB. Dynamic linking to system GTK4. Rust/Slint at 30MB bundles its own renderer. Only Rust editions have release binaries built.

Most concise: Python at 564 LOC. Go/Fyne at 3,490 LOC is 6x more verbose. Python benefits from shared framework-independent layers.

C release binaries NOT built. The main app binaries (fastnote) were not built for C editions because they require display context (GLFW/GTK4/Raylib). Only test binaries exist (61KB each).
